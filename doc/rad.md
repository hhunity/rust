# RadonPy とは何か 〜総まとめ〜

## 1. RadonPy の位置づけ

RadonPy は **CNN でも GNN でもない**。深層学習モデルではなく、高分子材料の物性を
オールアトム古典分子動力学(MD)シミュレーションによって自動計算する
オープンソースの Python ライブラリである。

- 入力: 化学構造(SMILES など)
- 出力: 密度・屈折率・ガラス転移温度・比熱・熱伝導率などの物性値
- 処理: 量子化学計算(電荷計算)+ MD シミュレーションのパイプラインを完全自動化

RadonPy 自体は「学習するパラメータ(重み)」を持たず、物理シミュレーションで
物性を**計算**しているだけであり、過去データから**予測**しているわけではない。

## 2. 使われている主な計算エンジン

| ツール | 役割 |
|---|---|
| **RDKit** | SMILES から分子の立体構造を組み立てる(化学構造の入出力) |
| **Psi4** | 量子化学計算(DFT)。原子の部分電荷などを精密に計算 |
| **GAFF2** | 力場(原子同士の相互作用ルール)を割り当てる |
| **LAMMPS** | 分子動力学(MD)シミュレーションの実行エンジン |

## 3. 入力パラメータ

線状ポリマーの非晶質状態を計算する場合、必要な入力は以下の5つ:

1. **SMILES 文字列** — 繰り返し単位(モノマー)の化学構造
2. **重合度** — 繰り返し単位が何個つながるか
3. **ポリマー鎖の本数** — シミュレーションセル内に入れる鎖の数
4. **温度**
5. **圧力**

## 4. 自動計算ワークフロー

1. モノマーの配座探索
2. DFT による電子的性質(原子電荷など)の計算
3. 自己回避ランダムウォークによるポリマー鎖の初期配置探索
4. GAFF2 による力場パラメータの割り当て
5. 等方的な非晶質セルの生成
6. 平衡化のための MD シミュレーション
7. 平衡状態への到達判定
8. 熱伝導率計算のための非平衡 MD(NEMD)シミュレーション
9. 後処理段階での物性計算

すべて自動で流れるため、実験室での合成・測定なしに大量の候補ポリマーの
物性を計算で予測できる。

## 5. RadonPy と機械学習の関係

RadonPy 自体は ML モデルではないが、**RadonPy が生成した大量の計算データ**は
別のニューラルネットワークの**事前学習(pretraining)**に使われることがある
(例: `docs/CECAM_tutorial/Transfer_Learning` 配下の transfer-learning notebook)。

### なぜ機械学習と組み合わせるのか

- 実験データは合成・測定にコストと時間がかかり、数百件程度しか集まらないことが多い
- RadonPy なら計算だけで数万件規模のデータを作れる
- 「大量の計算データ → 少量の実データへの知識転移」が Transfer Learning の狙い

## 6. Transfer Learning(転移学習)の仕組み

### 基本の流れ

1. RadonPy(または PolyOmics データベース)で大量の高分子物性を計算する(ソースデータ)
2. そのソースデータでニューラルネットワークを**事前学習(pretraining)**する
3. 少数のターゲットデータ(実験値、または別の物性)でネットワークを
   **ファインチューニング(fine-tuning)**する
4. ソースデータのみで学習した場合や、ターゲットデータのみで学習した場合より
   高い予測精度を得ることを狙う

### 事前学習は「借り物」ではなく自前データ

- 外部の汎用学習済みモデル(画像分野の ImageNet 事前学習モデルのようなもの)は使っていない
- **RadonPy / PolyOmics 自身が生成した計算データ**が事前学習の元データ
- つまり「計算(シミュレーション)で作った大量の疑似データ」を、
  事前学習用データセットとして自前で用意している

### モデル構造は CNN ではない

- 記述子: 化学構造を **Morgan フィンガープリント(ECFP6, 通常 2048 bit)** で
  固定長の数値ベクトルに変換(RDKit の `rdFingerprintGenerator` を使用)
- モデル: ごく標準的な**全結合多層ニューラルネットワーク(MLP)**
  (PyTorch の `torch.nn.Module` で実装。エンコーダー3層 + 回帰ヘッド1層)
- 画像のような空間的近傍関係を持つデータではないため、CNN ではなく MLP が使われている
- GNN(分子をグラフとして直接扱う手法)とも異なる、シンプルな構成

### 学習の具体的な設定(特殊な仕組みは使っていない)

- フレームワーク: **PyTorch**(TensorFlow/Keras や scikit-learn ではない)
- オプティマイザ: Adam / AdamW(ごく一般的)
- 学習率: 0.001 前後
- バッチサイズ: 32 前後
- Early stopping: 数エポック改善がなければ打ち切り
- Attention機構や巨大な事前学習済み基盤モデルは使われていない

### ファインチューニング時の2パターン

1. **ソースとターゲットが同じ物性**(例: 密度→密度)の場合
   → ネットワーク全体の重みをそのまま初期値として使い、再学習させる
2. **ソースとターゲットが異なる物性**(例: 密度→体積弾性率)の場合
   → 最終層(回帰ヘッド)だけリセットして新規初期化し、
     エンコーダー部分(化学構造の特徴抽出部分)だけを転用する
   → `model.reset_head()` のような処理で実現

## 7. 学習データとして実際に使われているもの

CECAM チュートリアルの transfer-learning notebook の例では:

- **事前学習データ**: PolyOmics データセット(RadonPy 計算による約 95,000 件の高分子物性、
  Hugging Face で公開)の中の `density`(密度)ラベル、最大 16,384 件を使用
- **ファインチューニングデータ**: 同じ PolyOmics データセットの `bulk_modulus`
  (体積弾性率)ラベル、256 件のみ
- **評価用テストデータ**: 同じく `bulk_modulus` ラベルの別の 1,024 件

つまりこの例では「密度データは大量にあるが、体積弾性率データは少ない」という
状況を模擬し、**異なる物性間**での転移学習の効果を検証している。

## 8. Sim2Real 転移学習とは

「シミュレーション(Sim)で学んだことを、実世界(Real)に応用する」という
転移学習の一種。元々はコンピュータビジョン分野(3DCG 画像で事前学習 →
少量の実写真でファインチューニング)から来た概念。

### 材料科学での対応関係

| Sim2Real の要素 | 材料科学での対応 |
|---|---|
| Sim(シミュレーション)側 | RadonPy の MD シミュレーションによる計算値(density, Cp, 屈折率など) |
| Real(実世界)側 | 実験室で測定した物性値(PoLyInfo データベースなど) |

流れ:

1. RadonPy の計算データ(数万件)で**同じ物性**を予測するモデルを事前学習
2. 実験室で測定した**同じ物性**の少量データでファインチューニング
3. 計算値と実験値には系統的なズレ(バイアス)があるが、
   「化学構造→物性の傾向」という大枠を計算データから学べているため、
   少ない実験データでもズレを補正しやすい

論文(Minami et al., Scaling law of Sim2Real transfer learning)では、
この手法で密度・屈折率などの実験値予測において、
直接学習より明確に高い精度が得られることが報告されている。

### 「異なる物性間の転移」との違い

| | 何 → 何 | データの種類 |
|---|---|---|
| 本来の Sim2Real | 密度(計算) → 密度(実験) | 同じ物性、計算→実験 |
| CECAM tutorial の例 | 密度(計算) → 体積弾性率(計算) | 異なる物性、計算→計算(教育用の簡易版) |

## 9. 実験結果から見える転移学習の効果(実測値)

CECAM tutorial の実験(density → bulk_modulus, 5 repeat の平均):

| 手法 | MAE |
|---|---|
| 直接学習(ターゲット256件のみ) | 約 6.34億 |
| 転移学習(ソース16,384件で事前学習→ファインチューニング) | 約 6.04億 |
| **改善率** | **約 4.7%** |

### 考察

- 改善は見られるが、決して劇的ではない(誤差の範囲に近い程度)
- 理由:
  1. 密度と体積弾性率は**別の物性**なので、転移できるのは
     「化学構造の特徴の掴み方」という間接的な知識だけ
  2. ファインチューニング時に**出力層をリセット**するため、
     密度の知識のうち「構造→密度の直接対応」は失われる
  3. 元論文で効果が大きかったのは**同じ物性**の Sim2Real 転移であり、
     **異なる物性間**の転移はそもそも難易度が高い

### 転移学習が効きやすい条件

- ソースとターゲットが**同じ物性**(計算値→実験値など)
- ターゲットのデータが**極端に少ない**(数十件レベル)
- 物性同士が**物理的に強く関連**している
  (例: 密度とガラス転移温度は、どちらも分子のパッキングに依存する)

## 10. まとめ図

```
[SMILES + 重合度 + 鎖数 + 温度 + 圧力]
        │
        ▼
   RadonPy (RDKit + Psi4 + GAFF2 + LAMMPS)
        │  ← MDシミュレーションによる物性計算(学習なし)
        ▼
  数万件規模の物性データセット(PolyOmics などシミュレーションデータ)
        │
        ▼
  Morganフィンガープリント化(ECFP6) → 全結合NN (MLP, PyTorch) で事前学習
        │  ← ソース物性(例: 密度)を予測できるように学習
        ▼
  [同じ物性への転移]              [異なる物性への転移]
  重み全体をそのまま再学習          出力層だけリセットして再学習
        │                              │
        ▼                              ▼
    少数の実験/ターゲットデータでファインチューニング
        │
        ▼
     実世界での物性予測モデル
```

## 11. AutoMD_scripts フォルダの中身

RadonPy リポジトリ直下の `AutoMD_scripts/` は、高分子1件分の QM 計算〜MD 計算〜
各種物性計算を一連のパイプラインとして流すためのスクリプト集。`*.py`(本体)と
`*.sh`(環境変数で計算条件を指定する実行ラッパー)がペアになっている。

### スクリプト一覧と役割

| ファイル | 役割 |
|---|---|
| **0_qm.py** | 繰り返し単位(モノマー)の3D構造生成→配座探索→DFTによる構造最適化→RESP法による原子電荷計算→分極率計算(DFT)。パイプラインの出発点(量子化学計算)。 |
| **1_eq.py** | モノマーから高分子鎖を生成し、力場(GAFF2など)を割り当て、シミュレーションセルを構築、平衡化MDを実行して平衡状態に達したか判定(`sim.preset.eq`使用)。 |
| **2_rst_eq.py** | `1_eq.py`で平衡に達しなかった場合に、平衡化MDを再開(リスタート)する。 |
| **3_tc.py** | 非平衡MD(NEMD)による熱伝導率の計算(`sim.preset.tc`使用)。 |
| **4_tg.py** | NEMDによるガラス転移温度(Tg)の計算(`sim.preset.tg`使用)。 |
| **5_sp.py** | 溶解度パラメータ(SP、凝集エネルギー密度など)の計算(`sim.preset.sp`使用)。 |
| **6_ef_dp.py** | 交流電場印加MDによる動的誘電率・誘電損失(loss tangent)の計算(`sim.preset.ef_dp`使用)。 |
| 各 `*.sh` | 対応する `*.py` を実行するシェルラッパー。`RadonPy_DBID`(計算ID)、`RadonPy_SMILES`、力場、温度・圧力、OMP/MPI/GPU並列数などを環境変数で指定して起動する。 |

QM/MDで実際にシミュレーションを回して物性値を導出しており、単なる数式計算ではない。
READMEには "used in the data generation for our database project" とあり、
機械学習用の教師データ(PolyOmics など)を大量生成するためのハイスループット
計算パイプラインという位置づけ。

### 実行順序・依存関係

同じ `RadonPy_DBID` を指定すると `./<DBID>/` を共通の作業ディレクトリとして使い、
前段の結果(json/pickle)をそこから読み込む設計になっている。

```
0_qm.py (任意/推奨)
   ↓
1_eq.py (必須の起点)
   ↓ (平衡未達なら)
2_rst_eq.py
   ↓
 ┌─────────┬─────────┬─────────┐
3_tc.py   4_tg.py   5_sp.py   6_ef_dp.py   ← 互いに独立・任意選択・並列可
```

- `0_qm.py → 1_eq.py`: 必須ではないが推奨。`0_qm.py`の結果を`RadonPy_Monomer_Dir`/
  `RadonPy_Monomer_ID`で`1_eq.py`に読み込ませる。省略も可。
- `1_eq.py → 2_rst_eq.py`: 平衡未達の場合のみ必要。
- `1_eq.py → 3/4/5/6`: これらは`1_eq.py`(または`2_rst_eq.py`)が作った平衡構造を
  `work_dir = './<DBID>'`から読み込むため、**1_eq.py完了が前提**。
- `3_tc.py`・`4_tg.py`・`5_sp.py`・`6_ef_dp.py` **同士は独立**しており、任意の順番・
  必要なものだけ選択・並列実行が可能(`RadonPy_JSON_File`/`RadonPy_Pickle_File`を
  明示指定すれば`./<DBID>/`以外からも読み込める)。

### 計算時間

数式計算ではなく実シミュレーションのため、相応に重い。

- スクリプト中に `# For Fugaku`(理研のスパコン)向け設定のコメントが残っており、
  もともとHPC/クラスタでの実行を前提とした設計になっている。
- サンプルの`.sh`では`RadonPy_MPI=64`など数十並列がデフォルト。
- デフォルト系サイズは`RadonPy_NAtom=1000`(1鎖あたり)×`RadonPy_NChain=10`で
  系全体1万原子規模。

| スクリプト | 内容 | 目安 |
|---|---|---|
| 0_qm.py | DFT構造最適化+RESP電荷+分極率 | 分〜数時間(`wb97m-d3bj`は比較的重い汎関数) |
| 1_eq.py | 1万原子規模の平衡化MD | 数時間〜数日(密度0.05g/cm³からの圧縮過程を含む) |
| 2_rst_eq.py | 平衡未達なら追加MD | 前段と同程度、繰り返す場合あり |
| 3_tc.py〜6_ef_dp.py | NEMDでの物性計算 | それぞれ数時間〜1日程度(特に`6_ef_dp.py`は交流電場を何波長も流すため長め) |

1つの高分子を0→6まで通しで流すと、マルチコア/GPU環境でも数日仕事になり得る。
だからこそ環境変数でOMP/MPI/GPU並列数を細かく指定でき、DBIDごとにHPCのバッチ
ジョブとして大量投入する運用が前提の設計になっている。

## 12. docs/CECAM_tutorial のPDF資料まとめ(ポリマー初心者向け)

RadonPyリポジトリの `docs/CECAM_tutorial/` フォルダには、2026年7月2日のCECAM
(欧州の計算科学ワークショップ)でのチュートリアル資料が2つ入っている。

- `CECAM_Tutorial_RadonPy.pdf`(55ページ、林 慶浩さん)… RadonPy自体の説明
- `CECAM_Tutorial_transfer_learning.pdf`(5ページ、Tom Hamakawaさん)… そのデータを
  使ったAI予測(転移学習)の話

前提として、**「高分子(ポリマー)」とはプラスチックやゴム、繊維などの材料**のことで、
小さい分子(モノマー)が鎖のようにたくさんつながってできている。

### 12.1 資料1: RadonPy Tutorial(林さんパート)

#### 全体像

3段階のパイプラインになっている。

```
RadonPy(データを作る道具)
   ↓ 大量にシミュレーション
PolyOmics(できたデータを貯めるデータベース)
   ↓ そのデータでAIを訓練
AI予測モデル(少量の実測データにも応用できる)
```

#### RadonPyってどういう道具か

- 一言でいうと、**「化学構造の文字列(SMILES)を入れると、コンピュータの中でその
  材料を再現し、物性値(硬さ・耐熱性など)を計算して吐き出してくれる自動化ツール」**。
- 実際に実験室で材料を作らなくても、コンピュータの中に仮想的にその材料を再現し
  (=分子動力学シミュレーション、MD)、その挙動から物性を計算する。
- 開発のねらいは「AIの学習に使える**大量のデータ**を、実験なしに用意すること」。
  なので精密さより**スピード(高スループット)を優先**する設計思想(多少不正確でも、
  後でAIが補正すればいい、という考え方)。
- 誰でも使えるように、細かい設定を意識しなくても代表的な計算が自動でできる
  「プリセット」機能が用意されている。
- 無料のオープンソースソフトだけで構成されていて、Pythonのデータ分析ツールとも
  組み合わせやすい。

#### どうやって計算しているか(ざっくり)

1. 材料の繰り返し単位(モノマー)の化学構造を入力
2. その構造の一番安定な立体的な形を探す(色々な形を試して一番エネルギーが低い
   ものを選ぶ)
3. 電子レベルの精密な計算(量子化学計算)で、原子がどれくらい電気を帯びているか
   等を求める
4. モノマーを鎖状につなげてポリマー鎖を作る
5. そのポリマー鎖を10本程度、箱の中にランダムに詰め込んで「アモルファス
   (非晶質、ぐちゃぐちゃに絡み合った)構造」を作る
6. その箱の中で仮想的に原子を動かし続けるシミュレーション(MD)を行い、安定した
   状態(平衡状態)になるまで待つ
7. 安定したら、そこから密度・耐熱温度・熱の伝わりやすさ・電気的な性質など、
   **60種類以上の物性値**を計算する

計算できる物性の例(身近な言葉で):
- **密度**、**ガラス転移温度Tg**(プラスチックが硬い状態から柔らかいゴム状に
  変わる温度)
- **熱伝導率**(熱の伝わりやすさ)
- **誘電率**(電気をどれだけ通しにくいか。スマホ基板などに重要)
- **溶解度パラメータ**(その物質が他の物質とどれくらい混ざりやすいか)
- 弾性率(硬さ)、屈折率(光の曲がり方)など

#### シミュレーションと実験のズレ

- 密度や熱伝導率、屈折率などは実際の実験値と**よく一致**する。
- 一方、比熱やTg、誘電率などは**系統的にズレる(バイアスがかかる)**ことが
  分かっている。
- なので「シミュレーションの値をそのまま使う」のではなく、後述の転移学習で
  **実験データを使って補正する**、という戦略を取っている。

#### PolyOmicsデータベース

- RadonPyを使ってスーパーコンピュータで2022年1月から計算を開始し、2025年10月
  時点で**約13万種類の高分子**(5百万データ点、21のポリマークラス、62種類の
  物性)のデータを蓄積済み。
- Hugging Face(AI業界でよく使われるデータ公開サイト)で無料公開されている。

#### まとめ(このパートの結論)

- RadonPyは「材料の物理シミュレーションツール」というより、**「AI時代のための
  データ生成マシン」**という位置づけ。
- 精度より量(スループット)重視。
- シミュレーションのデータは完璧ではないが、AIの下準備(転移学習の元データ)
  としては十分役に立つ。

残りの後半ページ(AutoMD_scriptsの各スクリプトの対応、SMILESからのモノマー生成・
配座探索・力場割り当て・アモルファスセル生成・平衡化MD・NEMDによる熱伝導率/Tg/
溶解度パラメータ/誘電特性の計算など)は、実際にPythonでどう書くかという
プログラミングの詳細なAPI仕様・関数リファレンス・付録であり、本ドキュメントの
「11. AutoMD_scripts フォルダの中身」の内容と対応している。

### 12.2 資料2: Transfer Learning(Hamakawaさんパート)

#### 問題設定

- ポリマー材料の研究は「熱伝導率」「Tg」「気体の通しやすさ」など、**課題が
  ものすごく細分化**されている。
- しかも各研究室・企業がそれぞれ独自の、小規模でバラバラなデータしか持っていない。
- AIは基本的に**データが多いほど賢くなる**性質があるが、1つの研究室のデータ
  だけでは足りない。
- さらに、「今まで見たことがないタイプの化学構造」を予測しようとすると精度が
  ガクッと落ちる(=未知の領域への外挿は苦手)。

#### 解決策: 大量のシミュレーションデータで「地ならし」してから、少量の実データで仕上げる

- RadonPyで作った**大量の計算データ(PolyOmics、13万件、500万データ点、62種類の
  物性)**を使って、まずAIモデルにポリマーの化学構造と物性の関係のおおまかな
  傾向を学ばせる(=**事前学習**)。
- そのあとで、自分の手元にある少量の実験データだけを使って、その学習済み
  モデルを**微調整(ファインチューニング)**する。
- イメージとしては「大量の教科書で一般知識を身につけた学生に、少ない過去問
  だけで特定の試験対策をさせる」ようなもの。

#### 効果があるという根拠(スケーリング則)

- 事前学習に使うデータの量を増やすほど、最終的な予測の誤差(テスト誤差)が
  着実に下がっていくことが実験で確認されている(データが増えるほど賢くなる、
  という関係=スケーリング則)。
- これが成り立つからこそ、「とにかく大量のシミュレーションデータを用意する」
  というRadonPy/PolyOmicsの戦略に意味がある、という結論。

### 12.3 2つの資料をつなげると

```
[RadonPy]                 [PolyOmics]                [AI予測モデル]
実験なしで               13万種類のポリマーの        少しの実験データだけで
材料をシミュレーション   物性データベース             精度の高い予測ができる
  → 物性を計算    →      (事前学習用の教材)    →     (Sim2Real 転移学習)
```

「実験室でしか分からなかった材料の性質を、シミュレーションで大量に作り出し、
それを"予備知識"としてAIに教え込むことで、少ないリアルなデータからでも高精度に
材料の性質を予測できるようにする」というのが、この2つの発表全体の狙いである。
