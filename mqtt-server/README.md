# mqtt-server（パソコン役）

[`rumqttd`](https://crates.io/crates/rumqttd)（MQTTブローカー）と、[`rumqttc`](https://crates.io/crates/rumqttc)
を使った「パソコン役」の指示出しロジックを、同じバイナリに同居させたプロジェクトです。
`mqtt-client`（マイコン役）プロジェクトとは独立しており、単独でビルド・実行できます。

なぜ同居させているかというと、パソコンは「ブローカー」と「指示を出すクライアント」の
両方の役割を担うため、いっそ同じソース・同じプロセスにまとめてしまった方がシンプルだからです
（マイコン役は今まで通り`mqtt-client`という別プロジェクトのままです）。

## 使い方

```sh
cargo run -- [ポート番号] [名前] [トピック]

# 例（すべて省略してデフォルトのまま起動）
cargo run

# 例（ポート・名前・トピックを指定）
cargo run -- 1883 pc chat
```

引数はすべて省略可能で、それぞれ `1883` / `pc` / `chat` がデフォルトです。

起動すると、まずMQTTブローカーが`0.0.0.0:<ポート番号>`で待ち受けを始め、続けてこのパソコン自身が
`127.0.0.1:<ポート番号>`へ普通のMQTTクライアントとして接続します。マイコン役（`mqtt-client`）は、
このポートに向けて接続してきます。

行を入力して Enter を押すと `<名前>: <入力内容>` がチャットとして`<トピック>`にpublishされます。
`Ctrl+D` で送信スレッドを終了できます。

入力行の先頭に `/qos0 ` `/qos1 ` `/qos2 ` を付けると、そのメッセージだけQoSを指定して送信できます。
省略した場合はQoS1（AtLeastOnce）です。

## ファイル送信（`/send`）

```
/send <宛先の名前> <ファイルパス>

# 例
/send device1 ./photo.png
```

MQTTは大きなバイナリデータの配信には向いていないため、**ファイルの中身そのものはMQTTに乗せず、
別途つないだ生のTCPソケットで直接送受信**する方式にしています。

1. パソコンが `<topic>/file/offer/<宛先名>` トピックへ「このファイルを送りたい」という申し出をpublish
2. 宛先のマイコンが、自分の待ち受けアドレス（IP＋固定ポート）を `<topic>/file/ack/<pcの名前>` トピックへ返す
3. パソコンがそのアドレスへ直接TCP接続し、`id`＋ファイル名＋サイズ＋中身の順に流し込む
4. マイコン側は受信が終わった（または途中で失敗した）ら、結果を `<topic>/file/received/<マイコン名>`
   トピックへ`{"id": "...", "who": "device1", "status": "ok", "size": 12345, "seq": 4}`としてpublishする

パソコンはこのトピックをワイルドカード購読しているので、送信結果がその場の画面で確認できます。

## ジョブの一斉配信（`/job`）

```
/job <内容>

# 例
/job print A4x3
```

「今オンラインになっている全マイコンへジョブを配り、全員の完了報告が揃うまで待ってから次のジョブを
送る」という直列実行を行うコマンドです（印刷ジョブキューのような用途を想定）。

- マイコンは接続時に自分のpresenceトピック（`<topic>/presence/<名前>`）へ`"online"`をpublishし、
  異常切断時にはLast Willで自動的に`"offline"`が配信される。パソコンはこれをワイルドカード購読して
  「今どのマイコンがオンラインか」を動的な名簿として持っている（固定リストの設定は不要）
- `/job`実行時点でオンラインな全マイコンへ`<topic>/job/queue`にジョブをpublishし、
  各マイコンからの完了報告（`<topic>/job/done/<マイコン名>`）が全員分揃うまで入力をブロックして待つ
- 一定時間（デフォルト10秒）応答が無いマイコンがいた場合は、そのマイコン名を挙げてエラー表示する

## プロジェクトの中身

- `src/broker.rs` — MQTTブローカー（rumqttd）を起動するだけのモジュール
- `src/controller.rs` — パソコン役の指示出しロジック（チャット・`/send`・`/job`）
- `src/messages.rs` — MQTTでやり取りするメッセージの形（JSON、`mqtt-client`の同名ファイルと同じ内容）
- `src/seq.rs` — メッセージ欠落検知用のseq番号の仕組み（`mqtt-client`の同名ファイルと考え方は同じ）
- `src/main.rs` — 上記を起動して繋ぎ合わせるだけの薄いエントリーポイント

`messages.rs`と`seq.rs`は`mqtt-client`側にも同じ内容のファイルがあります。2つのプロジェクトは
意図的に別々のCargoクレート（共有ライブラリなし）にしているため、通信フォーマットを変えるときは
両方のファイルを一緒に直す必要があります。
